05 · ① 云效议题闭环
05 / 14
权重 30% · 全篇最重

从一条议题，
到一个可交付的方案

旧流程：在云效看到一条 bug，想交给 AI 修——复制议题描述、手动提炼成提示词、开终端、等它跑完、再回云效手写一版「改了啥」的评论。中途想先出个方案看看？没有地方放。

Nezha 把它压成一条链路：议题行右侧直接起任务或发起讨论，方案、待办、依赖、回写全部落在同一条链路上，产物是两份可移交的文件——plan.md（人读）与 deps.json（机器读）。

02生成待办只生成 todo，人工把关后再跑
03依赖门禁拓扑排序串行放行

等待不空转

前置未全部 done 的待办停在 waiting_deps，完成后自动放行；等待中不创建 PTY。

失败不静默

前置失败 / 取消 / 中断 / 缺失时标红 + 只通知一次，由人决定「忽略依赖，仍然开始」——门禁只作用于方案待办。

成环不死锁

解析刻意宽松：文件损坏只是少一道护栏；依赖成环时环上的边全部丢弃。放行受 max_concurrent（默认 1 = 串行）约束。

方案看板：Alt+K / ⌘+K →「方案」标签页 · 左栏方案列表，右栏依赖关系图（左→右 = 执行顺序）
08 · ② 计划与合并请求
08 / 14
权重 25%

把散落的分支，收口成一个 MR

PLAN · MERGE REQUEST

以前要先在云效创建分支，再回到本地切到对应分支改内容——但哪些议题改在什么分支上，没有地方能查看和规划。

01

计划是什么

一组有序议题 + 一条分支 +（可选）一个 worktree。类型 feature/fix/patch/project/hotfix；源分支按「类型/版本/目标分支/描述」自动生成，可手改并「检测」重名。

02

议题与分支的关系可查

议题表状态与方案关联全自动派生（已完成 / 执行中 / 已结束 / 讨论完成 / 讨论中 / 未开始），自上而下取第一个命中，没有手动维护入口——「哪个议题在哪条分支」变成一个可看的视图。

03

四级目标分支推断

手动指定（跨会话记住）> 项目配置 > 按分支名推断（hotfix/…/master/… → master）> 默认值。改一行只重算该分支——系统按你们的命名规范替你判断，不用每次手选。

权重 15%
Agent 先替你 读一遍代码

01 · SOURCE

来源与同步

本地目录或 git 远端（仅 https:// / git@）。首次完整 git clone，不用浅克隆；已存在则 git fetch 探测，有变更才 --ff-only 拉取（不 reset、不覆盖本地改动）。

每 15 分钟自动拉取 · 失败静默沿用缓存并退避
02 · INSTALL

安装 = 软链

装到项目 / 全局的技能是指向 Hub 内目录的软链——Hub 更新后已安装技能自动跟随，无需重装。健康标记 ok / broken（目标丢失）/ diverged（路径被外部修改）。

清理失效安装只删软链与安装记录
03 · DATA

数据与项目化

带数据目录的技能可打开文件夹 / 备份 / 重新构建，由 NEZHA_SKILL_DATA_DIR 注入并随仓库 git 管理。SkillHub 本身注册为一个特殊项目，可在普通任务 / 文件 / 终端视图里编辑技能内容。
