# Nezha v0.41.0 发版公告

Nezha v0.41.0 正式发布！本版聚焦 Codex full_access 模式的体验闭环：模型提问不再打断你，30 秒无人应答自动按推荐项继续；同时修复误报「等待输入」、方案讨论占坑、中文输入法按键冲突等一批问题。

## 🚀 新特性

### Codex 流式会话（codex）
- **full_access 下模型提问 30 秒自动应答**（`43135dc`）：此前 full_access 模式禁用了 Codex 的提问工具，模型有疑问只能硬猜着继续。现在提问照常弹出问答卡片，**30 秒无人应答时自动按推荐项（每题首个选项）应答并继续任务**；你随时可以手动回答，先答则定时器静默让位。前端问答卡片顶部有倒计时提示条，自动应答后撤卡恢复输入框。该行为为 Nezha 定制（ZCode 的超时仅报超时、不替用户做决定），只在 full_access 模式生效，ask / auto_edit 不受影响。

## 🐛 问题修复

- **full_access 任务被误标「等待输入」**（`7cfd9d7`）：full_access 下 Codex 不会请求任何审批，但两处与权限档无关的路径仍会把任务误标成 input_required——structured 通道的提问工具在免审批模式下不再注册；PTY/JSONL 通道对 `npm test` 等普通命令的「本地白名单猜测」不再把任务标成待确认。真正的提问与中断信号仍然保留。
- **方案定稿后执行任务卡在排队**（`0738f3f`）：方案讨论任务停留在待评审状态时会一直占用方案唯一的一个并发槽位，导致定稿后生成的执行任务永远排队等依赖，直到手动把讨论标记完成。现在方案离开草稿态后讨论任务不再占槽（草稿期照旧占用）；等待视图的占位列表同步修正。另外单议题方案的名字从「QHDK-X 联合方案」修正为「QHDK-X 方案」，多议题方案保持「联合方案」措辞。
- **拼音输入时按 ESC / Enter 误触终端操作**（`390a83a`）：输入拼音候选词时按 ESC 会打断正在运行的 turn（缺 IME 守卫），Enter 在部分输入法/WebView 组合下漏判提交态（keyCode 229）。现在提交流与中断流统一按 `isComposing || keyCode === 229` 守卫，@提及弹窗不再抢占输入法组合期间的 Enter/Tab/ESC/方向键。
- **重型组件测试随机超时**（`1e911bf`）：yunxiao 系列测试在全量并行跑时随机落在 5000ms 默认超时之外（实测 5120–5274ms，单跑稳定 ≤2.8s），每轮挂的用例还不一样。Vitest 超时上限提高到 20s，只约束真正慢的场景，断言失败仍立即报错。
