# Nezha v0.43.0 发版公告

Nezha v0.43.0 正式发布！本版修复 Codex 并发审批遗漏与等待状态不准确的问题，统一计划执行的默认权限，并移除无人值守模式。

## 🐛 问题修复

### Codex 审批与会话（codex）

- **并发审批按顺序保留，避免遗漏请求**（`ff07897`）：同一任务同时收到多条审批时，逐条展示尚未处理的请求；处理当前请求后，继续展示下一条。重复或延迟返回的应答不再误清除后续请求。
- **仍有审批或提问时保持等待状态**（`ff07897`）：只要还有阻塞交互未处理，会话就继续等待用户；应答发送失败时保留重试机会，避免界面显示已继续、智能体却仍在等待。

### 依赖与构建（deps）

- **修复 Markdown 解析依赖的安全审计失败**（`04dc60e`）：将 pulldown-cmark 升级到 0.13.6，修复 RUSTSEC-2026-0433 指出的嵌套图片 wikilink 解析耗时问题，恢复 CI 安全审计通过。

## ⚠️ 行为变更

### 计划执行（plan）

- **移除无人值守模式与自动完成行为**（`28356fe`）：不再提供无人值守开关，也不再因该模式强制使用完全访问权限、自动将一轮结束的任务标记完成或抑制待确认通知。任务等待确认时，需要用户处理并按实际情况标记完成，下游任务再按依赖条件启动。
- **三个计划执行入口统一使用项目默认权限**（`28356fe`）：方案预览页「开始」、生成待办确认页和议题快捷执行均读取项目配置中的默认权限；未配置或读取失败时使用询问模式。确认页中临时修改权限只影响本次创建，不再保存为下次默认值。
- **历史任务保留数据兼容**（`28356fe`）：历史无人值守标记仍可读取和保存，但升级后不再触发无人值守行为。依赖旧流程自动收尾的用户，请留意任务确认与完成状态。
