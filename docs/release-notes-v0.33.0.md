# Nezha v0.33.0 发版公告

Nezha v0.33.0 正式发布！本版本的两条主线是**任务可以跨仓库取上下文**（一个任务同时读改多个 Nezha 项目）与**云效议题列表变成可操作的入口**（行上直接看到方案进行到哪一步并就地推进）；此外把上一版引入的「提问方式」开关从应用设置搬到发起弹窗，并修掉了三个排队 / 过滤相关的现场问题。

## 🚀 新特性

### 智能体（agent）

- **跨仓库任务上下文**（`b4b2870`，#113）：一个任务此前只能看见自己所属项目，改一处联动代码就得反复切项目。现在新建任务时可以勾选额外的 Nezha 项目作为上下文，启动时其路径会以 CLI 原生的 `--add-dir` 传入（Claude Code 与 Codex 都支持该参数，可重复），agent 能在同一个任务里跨仓库阅读与修改；新建视图新增可搜索的仓库选择器，并**按项目记住上次的选择**；右侧面板的范围选择器也会列出已附加的仓库，跨仓库改动可以直接在那里 diff / 暂存 / 提交。路径在启动前会做存在性、目录类型与去重校验，任一条不合法即报错——不静默降级，避免 agent 拿到残缺上下文而用户不知情。
- **Codex 任务自动命名**（`f9e98f3`）：Codex CLI 会把每个会话的摘要标题写进 `~/.codex/session_index.jsonl`，Nezha 现在读取它来命名任务：会话发现时查询一次，运行中的任务每 45 秒轮询，已结束的任务回填一次。**手工重命名或 sparkle 生成的名字不会被覆盖**，只有回落到 `task-<id>` 的占位名才会被自动替换。

### 云效集成（yunxiao）

- **议题行显示方案状态并可就地操作**（`db7848f`）：议题列表此前看不出这条议题是否已经讨论过、方案进行到哪一步，必须离开列表去方案板找。现在每一行按议题 ID 反查所属方案，展示八种状态之一（讨论中 / 需要回答 / 讨论未完成 / 已定稿 / 执行中 / 已完成 / 直接执行占用 / 无方案），并把原来固定的三个按钮换成随状态变化的动作：回答等待中的讨论、继续中断的讨论、启动或继续执行方案、查看方案、删除重议、取消方案。状态与按钮由同一处派生，**角标和按钮不会再互相矛盾**；新增的方案查看弹窗会按依赖顺序渲染 `plan.md`（或 `preview.html`）并给出同样的动作，正在执行的方案不必绕道方案板就能收尾。另外，删掉讨论任务不再让方案消失——孤立方案保持可见，行内继续提供启动 / 重议 / 取消，而不是退化成「无方案」。
- **提问方式改为发起时选择**（`ff1bf5a`，`d7058b9`）：逐条盘问 / 批量盘问 / UI 盘问三个档位此前是应用设置里两个互斥开关，切一次要进设置页。现在改成发起讨论弹窗、直接开始弹窗、待办讨论视图三处都带一个三态按钮，点击在「逐条 → 批量 → UI」之间循环，**选择被记住并在这三个入口间共享**；方案执行链路保持固定逐条盘问不变。详见下方「行为变更」。
- **价值评分支持 v2 绩效指数**（`450ef0b`）：`issue-value-scoring` 技能升级到 v2 后，Bug 评分新增「绩效指数 = 优先指数 × 研发贡献系数」。解析按绩效指数 > 核心指数 > 优先指数取值，**旧格式的历史评论回代不丢值**——此前已回写过评分的议题重新读取仍能取到原来的优先指数。

## 🐛 问题修复

- **崩溃重启后不再提前放行排队中的待办**（`8606875`）：重启时任务先于方案依赖载入（依赖刷新是即发即忘），首个调度拍看到的是空依赖缓存，而调度器把「无缓存条目」当成「没有依赖」，于是 `waiting_deps` 的待办被直接启动，**同时绕过了依赖门禁与项目并发上限**。现在把「缓存缺条目」识别为「依赖尚未载入」，该拍跳过此方案，等依赖到位后按正常门禁放行；确实无依赖的方案不受影响（载入过的方案一定会写入条目，哪怕是空图）。
- **「本周 / 本月」过滤偏好不再在首次查询时失效**（`dc0e3a3`）：带着时间预设进入议题页时，首查守卫只等过滤偏好恢复、不等自定义字段 ID 探测，而探测又会先把字段 ID 清成 `null`，两者叠加导致首个请求不带时间条件——列表先渲染全量再重查校正，表现为「过滤器选中但列表显示全部」。现在已探测到的字段 ID 随过滤偏好一起按项目持久化并在挂载时同步恢复，首查即可带上 BETWEEN 条件；探测改为纯后台增量刷新（失败保留缓存值）；本项目从未缓存过字段 ID 时首查等探测结束再发，并带 5 秒兜底超时，网络挂死也不会让列表永久空白。
- **等待中的待办不再显示自相矛盾的原因**（`3904979`）：等待视图靠「门禁是否有条目」来区分「等前置」与「排队等槽位」，但依赖未载入时门禁同样是空的，于是依赖尚未解析的方案会显示成「排队中 —— 等待本项目空出槽位」，而此时项目里一个任务都没在跑。现在显式区分三种原因：等前置、等槽位（**并列出占着槽位的任务**，此前算出来但从未展示）、以及依赖仍在读取——任务列表与详情页的角标同步获得第三种状态。

## ⚠️ 行为变更

- **设置页的「批量盘问 / UI 盘问」开关移除**（`ff1bf5a`，`d7058b9`）：v0.32.0 引入的两个互斥开关（应用设置 → 技能库）已删除，提问方式改为在**发起讨论 / 直接开始**的弹窗里用三态按钮（逐条盘问 → 批量盘问 → UI 盘问）当场选择，并记住上次选择、三个入口共享。原开关的取值不再被后端读取，`settings.json` 里残留的 `batch_grill_enabled` / `grill_with_ui_enabled` 字段会被忽略，**升级后首次发起讨论的提问方式是「逐条盘问」**（除非在弹窗里切换）。UI 盘问仍需先在技能库安装 `grill-with-ui` 技能并具备 Node 20+，未安装时按逐条节律降级。帮助文档「UI 盘问说明」的第 1 节已同步改写为弹窗选择方式，并移除了对应的设置页截图。
