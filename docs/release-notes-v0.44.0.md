# Nezha v0.44.0 发版公告

Nezha v0.44.0 正式发布！本版带来合并审核双栏界面与关闭合并请求功能，并上线 Codex 结构化对话的下一条 Prompt 建议，改善续聊、草稿保护和会话退出体验。

## 🚀 新特性

### 合并审核（codeup）

- **请求列表与详情分栏展示**（`b879f91`）：左侧选择合并请求，右侧查看分支、审核人和合并前检查，集中执行拉取、审查与合并；支持搜索、仓库筛选、分页及窄窗口布局。
- **直接关闭云效合并请求**（`b879f91`）：确认后调用真实关闭接口，成功后移入「已关闭」，失败时保留请求并显示原因；源分支、本地代码与审查报告保留。「已关闭」从云效查询，刷新后仍可查看最近记录。
- **审查报告保留完整处理流程**（`b879f91`）：在独立弹窗查看、复制和导出报告，也可编辑后回写到合并请求评论；操作期间防止重复提交。

### Codex 下一条 Prompt 建议（codex）

- **对话结束后提供可选的下一步建议**（`9d15d5f`、`4b3a5bc`）：在支持的结构化会话中，空输入框可显示根据当前对话生成的建议；仅在已验证的 Codex 构建、模型和服务商组合下启用，不支持的环境继续使用普通输入框。
- **Tab 接受为草稿，仍由用户决定发送**（`b034e28`）：建议不会自动发送；接受后可以编辑，也可以撤销。建议使用较淡文字显示，避免与用户已经输入的内容混淆（`f0ed47e`）。
- **支持已验证稳定版的 Sol 模型组合**（`5291108`）：扩展下一条提示预测的兼容范围，仍保留运行时能力检查，不能仅凭版本号推断所有模型均受支持。
- **复用可继续对话的会话**（`377e0db`，#123）：统一管理结构化会话的使用权，在可复用时减少下一轮对话重新启动的开销。

## 🐛 问题修复

### Codex 对话与会话清理（codex）

- **等待启动确认后再发送，失败时保留草稿**（`e3d9080`）：避免任务尚未就绪就发送消息；启动或发送失败时保留输入文字和图片，便于重试，并避免启动期间加载历史记录干扰当前对话。
- **取消与清理不再影响后续对话**（`b150703`、`34c0d1a`、`db51ba3`）：修复启动中取消、附件清理与任务交接的时序问题，避免旧任务的延迟清理误伤新一轮。
- **及时丢弃过期建议并释放相关资源**（`59f4fc3`、`e71cb2a`、`048738a`、`26dcd33`、`db51ba3`）：预测失败、上下文改变、任务交接或全局设置变化后，不再继续展示或复用失效建议；取消后及时回收后台资源。
- **退出应用时收拢仍由应用持有的会话**（`6c09aaf`）：协调正在启动、执行或预测中的会话关闭，减少后台进程残留。
- **建议显示不再撑高输入框**（`5e88334`、`4b3a5bc`）：改善暗亮主题与窄窗口下的文字和控件布局，不支持预测时保持原有输入区尺寸。

### 应用设置（settings）

- **通用设置按用途分组**（`f0ed47e`）：按语言与任务列表、Codex 对话、通知与提醒、终端整理选项，简化说明，便于找到对应设置。

### 依赖与构建（ci）

- **更新 QUIC 相关依赖并明确审计范围**（`77a1a51`）：更新依赖锁定版本，并为仅作为协议依赖引入、未在 Nezha 中使用的相关能力记录审计例外。例外不代表独立安装的 Codex CLI 已完成安全更新。

## ⚠️ 行为变更

- **下一条 Prompt 建议默认启用**（`4b3a5bc`）：未设置该选项时默认开启；之前明确关闭的设置继续保留。该功能仅作用于符合兼容条件的结构化对话，会产生额外模型用量，可在应用设置中关闭。
- **移除输入框底部的发送快捷键提示文字**（`e3d9080`）：减少输入区视觉干扰；这项调整不取消原有发送快捷键。

## 📝 文档

- **补充预测功能规范与协议支持矩阵**（`fcc23b4`、`f517513`、`59f4fc3`、`5291108`）：记录支持条件、验证方法和兼容边界。
- **补充桌面验收记录**（`ab924a0`、`4b3a5bc`）：覆盖建议接受与撤销、暗亮主题、窄窗口及会话生命周期验证，保留验证范围与限制说明。
