# Nezha v0.37.0 发版公告

Nezha v0.37.0 正式发布！本版本主题是**让 Codex 结构化会话完整可回溯、可对话**：历史会话回放、模型反向提问卡片、技能提及全面升级，外加一批阅读体验改进。

## 🚀 新特性

### 结构化流视图（codex）

- **历史会话回放**（`fb33a1d`）：structured 任务的流式条目此前只活在内存里——重启应用或从任务列表打开一个已完成的历史任务时，只能看到「没有智能体活动记录」。现在新增 `read_codex_stream_history`，把 rollout 会话文件还原成与实时流同构的帧并复用同一套渲染链路，历史任务的思考、命令与结论完整可见。兼容 0.153+ 与 ≤0.146 两种落盘格式，折叠头能显示真实的「已工作 N 秒」而不是 0。回放带三道保护：失败不重试、实时帧到达即放弃回放、重跑任务可重新回放，不会出现重复渲染或死循环。
- **图片视图渲染**（`56fc0c8`）：`view_image` 工具的输出不再显示为原始 JSON 调试卡，改为渲染缩略图并带路径与尺寸信息，文件缺失时给出明确失败原因。
- **子代理活动合并**（`56fc0c8`）：子代理事件按线程 ID 合并为单张状态卡，任务结束后不再误标「运行中」。
- **回合分段折叠**（`56fc0c8`）：流视图按每条用户消息切分回合，过程性条目折叠为「工作了 N 秒」的可展开区块，最终答案保留在主线上一眼可见。
- **思考卡摘要化**（`56fc0c8`）：思考卡不再自动展开，摘要行持续流式显示最新思考；时长超过一分钟自动切换为分/时显示。

### 模型反向提问（codex）

- **提问卡片**（`92a48f2`）：Codex 的 `request_user_input` 工具此前被自动拒绝，模型拿不到答案只能退化成让用户手打编号选项。现在模型向你提问时会弹出逐题选项芯片 + 自由输入的提问卡，一次提交全部答案；跳过也会正确应答，回合不再挂起。
- **提问卡接线与优先级**（`c23cb5a`）：提问卡渲染在流底、审批卡之前（提问阻塞整个回合，优先级高于只拒绝单条命令的审批），两者同时挂起时不会叠两张卡片；提问挂起期间输入框禁用，新回合开始后上一轮提问自动失效。

### 技能提及（agent）

- **技能来源合并**（`6fd7d18`）：`$` 选择器此前只列出 SkillHub 里的技能，而 `~/.claude|codex|agents/skills` 与项目级 `.claude|codex/skills` 下的技能对智能体天然可见却搜不到。现在选择器合并全部四个来源，按名称去重（项目级 > 用户级 > SkillHub）、按字母排序，并用徽标区分技能来源。
- **紧凑技能芯片**（`6852cf2`）：选中技能不再把整句「请读取并遵循 xxx 技能：<路径>」塞进输入框，改为只写紧凑的 `$name` 芯片（可整体退格删除）；提交一刻才展开为完整指令，智能体收到的提示词与之前逐字一致。用户消息气泡、任务列表、看板、时间线与运行头部标题统一折叠显示为 `$名称`，悬浮可看完整路径。

### 阅读体验（markdown）

- **对话正文硬换行渲染**（`f5c5a74`）：模型回复常写成「`1. **小标题**` + 换行正文」，按 CommonMark 单换行会被折叠成空格，标题和正文并成一行。会话消息、计划预览、评审报告这类对话正文现在按 `breaks: true` 渲染（与 GitHub 评论区一致），段落结构清晰可读；真实 `.md` 文件预览保持标准 Markdown 语义不变。

## 🐛 问题修复

- **同一回合显示两个矛盾的工作计时器**（`c67953a`）：运行中的回合此前有两个独立计数的「工作中」指示器，各自从挂载时刻起算，同一屏幕可能显示两个不同的已用时长。现在计时器只保留回合头部一处，流尾指示器仅在消息刚发出、还没有任何过程条目时显示。
- **v0.36.0 构建产物缺失**（`1950fbc`）：Codex 协议的 git 依赖检出后其中一条文件名 193 字符，在 Windows CI 上拼接后超过 MAX_PATH=260 导致 cargo 构建中断，v0.36.0 首次发版没有产出任何安装包。现通过缩短 CI 上的 `CARGO_HOME` 并启用 `core.longpaths` 兜底；同时补上手动补跑入口——tag 不可重打，构建失败的版本可以给已存在的 Release 追加产物，且不会覆盖手写的发版公告。
- **线格式样例 JSON 损坏**（`aa8ded5`）：修复测试样例字符串里混入的多余终止符导致的解析失败。
