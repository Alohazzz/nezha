# Nezha v0.29.2 发版公告

Nezha v0.29.2 正式发布！本版本包含两大重点：**构建面板支持发现未在 .gitmodules 声明的一级嵌套仓库**（前后端仓库同项目并存场景），以及**云效回写的价值评分升级为独立第三条评论**（评分字段解析与开发评论解耦）。另有一处回写行为变更：**计划完成时间不再回写到议题**。

## 🚀 新特性

### 构建集成（build）

- **发现一级嵌套 Git 仓库**（`7f99d27`）：构建面板（build.rs）与仓库切换器（git.rs）现在会同时发现三类仓库——根仓库、.gitmodules 声明的子模块、以及项目下含 `.git` 的一级目录（跳过隐藏目录、node_modules、.nezha；子模块路径优先认领）。同一项目文件夹里并存的前端 / 后端仓库无需声明为 submodule 即可直接使用。
- **visible_subrepos 白名单默认放开**：前后端同步移除了硬编码的 DrugInOut/Term/Hsp.Win 默认白名单，改为不限制；已保存的存量配置保持不变。设置页选项来自同一套扩展发现逻辑（仍然不发起 git 调用）。
- **嵌套仓库成为一等公民**：pull / checkout / prune / 增量 diff 等操作对嵌套仓库与子模块同等支持。

### 云效回写（yunxiao）

- **价值评分独立为第三条评论**（`f8f2e15`）：回写现在把开发 / 测试 / 评分三段分别发布为独立评论，评分字段从评分评论输入解析——编辑开发预览不再悄悄破坏字段回写，大评分表也不再挤占开发评论的体积上限。草稿切分按标题提取评分段（包括 agent 把评分段写在测试段之后的 QHDK-30560 排布），并从两条正文中剥离；评分内联在开发段的旧草稿仍可通过 fallback 解析。评分评论发布失败降级为非阻塞警告（此时开发 / 测试评论可能已发出）。技能契约（SkillHub afad1c1）同步取消固定段落顺序。

## 🐛 问题修复

- **评分段提取回归修复**（`17450f0`，QHDK-30560）：agent 可能把价值评分段写在测试段之后、违反技能契约的段落顺序，按标题切分后只看开发段会丢失评分，导致开发评论缺评分、字段回写为空。现在改为从完整草稿提取，并从测试段剥离落入其中的评分段，避免重复发布。

## ⚠️ 行为变更

- **计划完成时间不再回写到议题**（`4c117b1`）：计划完成时间在 Codeup 侧属于用户自有字段——加入计划时写入它会在规划尚未开始时就冻结该字段，且 QHDK-30560 字段查询持续失败。现在加入计划只回写开始日期（默认当天）、负责人和开发状态；创建计划对话框在必填的完成日期缺失时会显式报错，不再静默返回。

## 📝 文档
