# Nezha v0.29.1 发版公告

Nezha v0.29.1 正式发布！本版本为补丁版本，聚焦**云效回写的两处正确性修复**：测试报告的「修改文件」改为从 git 确定性推导（彻底解决系统性漏报），移出交付计划的状态回写改为回到「已确认」（消除工作流不存在的状态流转导致的 400 报错）。

## 🐛 问题修复

### 云效回写（yunxiao）

- **测试报告「修改文件」改为 git 确定性统计**（`000ea5c`，fixes #106）：此前该字段由 LLM 凭会话记忆 / diff stat 归纳，存在五处系统性漏报（草稿过期、未提交变更不在 diff 事实里、plan.md 预判、base 缺失、8000 字符截断），实际修改的文件多于回写统计。现在回写生成时改为确定性统计三源并集：
  - `git diff --name-only {base}...HEAD`（已提交变更；base 缺失时回落 `@{20}..HEAD`）
  - `git diff --name-only HEAD`（已暂存 + 未暂存变更）
  - `git status --porcelain` 的未跟踪文件

  路径按一级目录归并成工程名，先归一字段名再覆盖字段值（幂等）；统计为空集时保持原文（宁缺毋错）。LLM 只负责测试步骤与方案描述。

- **移出交付计划的状态回写改为「已确认」**（`ea377e5`）：此前议题移出交付计划时状态回写到「待处理」，但多数租户工作流没有「待开发 → 待处理」的流转边，云效直接拒绝写入并返回 400。现改为回滚到「已确认」，与文档化的生命周期（待确认 → 已确认 → 待开发）一致。

## 📝 文档

- 新增「云效议题生命周期闭环」文档（`3298c4b`），记录从人工确认到归档的六步生命周期，移出计划回写描述与上述修复对齐。
