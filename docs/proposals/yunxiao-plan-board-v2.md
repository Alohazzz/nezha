## 1. 现状问题

v1 的看板（`PlanBoard` + `PlanGroup`）把「任务为主体、方案退为分组表头」做到位了，但聚合层级选错了：

| 问题 | 具体表现 |
|---|---|
| **一屏塞所有项目** | 按项目分组平铺，方案多了要滚很久；没有一个「我正在看哪个方案」的概念 |
| **没有导航层级** | 没有面包屑，切项目/切方案全靠滚动定位 |
| **依赖只有文字** | 每个任务行一个 `等 X` / `前置 X 已完成` 徽标，**看不到链路**：「谁卡住了谁」要一行行读出来 |
| **信息单薄** | 任务行只有 状态/编号/标题/依赖徽标/时长，没有变更统计、失败原因；动效为零 |
| **筛选器横贯全页** | 与主体内容抢空间 |

| **G4** | 图与列表联动 | 悬停互高亮；单击节点滚动定位到任务行；**只有行上的按钮才打开任务** |

| **T1** | 窄窗 | 退化为单栏钻取：列表 → 点方案进详情 → 返回 |

### 2.1 为什么不用 archify 的产物

SkillHub 的 `archify` 是**构建期 Node CLI**，产出**自包含静态 HTML**（内联 SVG + 自带 viewer）。方案目录下确实可以落盘 `deps-graph.html` 再 iframe 嵌进来，但：

- **图必须是活的**：任务状态一变，边要立刻从「未满足」变「已满足」。静态产物需要重生成（起 node + 渲染），做不到随状态变。
- **要点击跳任务**：iframe 内点击需要 postMessage 桥，而 `board.card` / `board.row` 的每个节点都要能定位到任务行。
- 它的 `visual-check` 会拉 Chrome 截图，属交付验收步骤，不适合放进每次渲染路径。

因此**取其视觉语言、不取其产物**：自己画 DAG，布局算法见 §4。

## 4. 依赖图布局（核心算法）

`utils/planGraph.ts::layoutPlanDependencyGraph`：

1. **分层**：最长路径分层（迭代式 Kahn）——`layer(n) = 1 + max(layer(前置))`，而不是「直接前置个数」。用最长路径才能保证所有边都从低层指向高层。
2. **列内顺序**：沿用任务行给定顺序（`derivePlanTaskRows` 已按拓扑序排列），因此同层自上而下读下来就是建议执行顺序。
3. **列内居中**：列高不同时上下留白均分，整列围绕中线展开而非顶对齐。
4. **边状态**：`done` → 满足（绿实线）；前置缺失/`failed`/`cancelled`/`interrupted` → 异常（红）；其余 → 未满足（黄）。

### 4.1 跨层边的通道（本轮实测发现并修复的真问题）

**相邻层**的边从列间空隙穿过，安全。**跨层边**（跳过至少一列）的直线/贝塞尔路由会**横穿中间列的节点盒**：

> 实测用例：`29753 → 29754`（层 1 → 层 3）的边从 `29751`、`29752` 的方框里穿过去。沿路径采样 200 点，有 57 个点落在 `29752` 盒内。视觉上这条边会被读成「29754 依赖 29752」，**把依赖关系画错**。

修法：跨层边统一降到**所有节点下方的独立通道**（每条错开一层，排序固定保证可复现），走「下潜 → 横穿 → 上升」圆角折线。通道几何由布局层给出 `laneY`，渲染层只负责拼路径。

**验证**：28 组随机 DAG（4–16 节点、含大量跨层边）逐条采样 400 点检查，**0 穿模 / 0 横向溢出**。

## 5. 动效清单（纯 CSS）

| 场景 | 效果 |
|---|---|
| 切换方案 | 详情内容淡入上浮 220ms |
| 任务行入场 | 逐行 stagger 40ms |
| 依赖边 | 按 `stroke-dashoffset` 从上游「画出」420ms（用 `pathLength=1` 归一化，与真实长度无关） |
| 图节点入场 | 逐个淡入，stagger 30ms |
| 运行中节点 | 外圈光晕脉冲 2.2s（只画描边不填充，不遮文字） |
| 左栏选中 | 指示条 `scaleY` 从中间展开（不引起重排） |
| 进度条 | 宽度过渡 + 数字变化淡入 |
| 项目节点箭头 | 展开时旋转 180° |

`prefers-reduced-motion: reduce` 下全部关闭，只保留状态色。

## 6. 实现中发现并修掉的真问题

| 问题 | 影响 | 修法 |
|---|---|---|
| **图节点序号用列内序号** | 同一任务在图里显示 2、在列表里显示 3，直接读错执行顺序 | 改用任务行索引（拓扑序） |
| **跨层边穿模**（§4.1） | 依赖关系被画错 | 独立通道 |
| **依赖图撑破页面**（1280px 下 1344 > 1280） | 整页横向溢出 | 补 `min-width: 0` 到 flex 链路（`plan-board-shell` / `plan-board-main` / `plan-detail` / `plan-detail-body` / `plan-graph-section`），让图区自己滚动 |
| **左右栏空态文案重复** | 筛选无结果时两栏都说「没有符合筛选条件的方案」 | 空态统一由左栏说明，右栏只留占位 |

## 8. 明确不做（本期范围外）

- **图内缩放/平移**：当前是容器滚动，第一版不做缩放交互。
- **依赖图编辑**：依赖的编辑入口仍在生成待办确认页（`planDeps` 的编辑器不动）。
- **跨项目总览**：交给任务看板 tab；方案看板锁定单项目。
- **「全部项目」合并视图**：不保留——保留两套跨项目视图会让左栏退回分组形态，冲淡「专注一个方案」。
