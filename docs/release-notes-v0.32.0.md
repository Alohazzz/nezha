# Nezha v0.32.0 发版公告

Nezha v0.32.0 正式发布！本版本主线是**讨论链路新增第三种提问方式「UI 盘问」**——把澄清问题从终端搬到本地浏览器页面，卡片式作答、每题独立讨论线程，并附带完整的帮助文档；另修复**云效回写「修改文件」被子模块指针污染、新分支丢失已提交变更**两个现场问题。

## 🚀 新特性

### 云效集成（yunxiao）

- **新增 UI 盘问提问方式（测试技能）**（`6c5efd2`）：讨论链路的提问方式此前只有逐条盘问与批量盘问两档，长盘问在终端里读起来慢、也不好回头翻。新增第三档 UI 盘问：问题放到本地浏览器页面，每题一张带选项的卡片，**任意顺序作答**，每题可开**独立讨论线程**，还能展开优缺点对照表（「展开利弊」）或让 agent 出原型 / 架构图（「可视化」）；作答期间终端保持等待，盘问结束产出设计文档。设置页「UI 盘问」开关（实验特性）开启后在「直接开始（先澄清）」与「方案讨论」两条链路生效，需先从技能库安装 `grill-with-ui` 技能并具备 Node 20+。
- **两档盘问开关应用级互斥**：批量盘问与 UI 盘问都改「提问方式」，同时开启会让下发的提问技能参数自相矛盾。现在保存命令、设置归一化与下发取值三层都保证至多一个生效——开启一个会自动关掉另一个，`settings.json` 被手工改成两开时保留 UI 盘问。方案产物契约不受影响：`plan.md` 结构、`deps.json`、性能影响分析强制分支、Bug 的取证流程全部不变。
- **入口文案跟随当前提问方式**：「直接开始」与「方案讨论」的按钮、流程提示会显示当前生效的提问方式（如「先做 UI 盘问澄清（grill-with-ui），再执行」），设置页的技能缺失提示也会按所选方式检查对应技能是否已安装。

## 🐛 问题修复

- **云效回写「修改文件」不再被子模块指针污染**（`6bb6182`，#109）：父仓库的 `git diff/status` 会把「子模块检出 commit 与索引记录不一致」报成普通路径（gitlink 指针），这些与本议题无关的路径参与归并后产出假工程名，并在草稿值正确时把它覆盖掉（现场案例 QHDK-29184：草稿里的 `Nto.His.Order.UI` 被覆盖成 `Hsp.Win`、`Nto.Emr`、`Nto.His`）。现在三处来源统一加 `--ignore-submodules=all` 剔除子模块漂移。
- **新分支不再丢失已提交变更**（`6bb6182`，#109）：base branch 缺失时的回落命令用当前分支 reflog 检索（`@{20}..HEAD`），新建分支只有一两条 reflog 必然 fatal，已提交的变更被整体判空。改为三级回落：base diff → 按议题编号检索提交（本议题改动必带 tag，不受分支新旧影响）→ 最近 20 条提交。子模块内部的改动本次不递归采集，判空时保留 agent 草稿原文，宁缺毋错。

## 📝 文档

- **新增「UI 盘问说明」帮助文档**（`0d4cd0a`）：帮助中心现为三份文档并列（操作手册 / 云效议题详解 / UI 盘问说明），新文档覆盖 UI 盘问解决的问题、开启方式（含与批量盘问的互斥关系）、作答与暂存机制、逐题讨论、展开利弊、可视化、术语表与收尾产出，配 9 张截图。两份旧文档补上指向新文档的交叉链接，并修正目录里序号与标题粘连的问题。
- 设置页「UI 盘问」提示里的按钮名改为与实际界面一致（「展开利弊」/「可视化」，此前写的是英文）。
- **依赖安全更新**（`502b553`）：`quinn-proto` 升至 0.11.19，清掉 RUSTSEC-2026-0338 ~ 0342 全部告警（该依赖经 reqwest 间接引入，攻击向量需可控 QUIC 对端，本项目未启用相关特性，属清理 `cargo audit` 门禁而非修复在网暴露）。
