# Nezha v0.35.0 发版公告

Nezha v0.35.0 正式发布！本版本主题是**终端滚轮与选区的彻底修复**：Codex 等鼠标上报型 TUI 运行期间，普通滚轮直接滚动、普通拖选直接划选区，不再需要按住 Shift。

## 🚀 新特性

### 终端（terminal）

- **本地滚轮接管：无需 Shift 直接滚动**（`3ac9419`）：Codex 0.16x 在任务运行期间开启鼠标上报，xterm 会把滚轮事件转发给 PTY 对端而不是本地滚动，此前只能靠 Shift+滚轮应急。现在终端容器在捕获阶段接管滚轮：备选缓冲区（全屏 TUI）下自行合成 SGR 鼠标滚轮上报发给 TUI 让它滚动回显，普通缓冲区下直接本地滚动。绕开了 xterm 内部依赖渲染器单元格度量 / DPR / 平滑滚动状态的静默丢事件链路，真机上普通滚轮从此「滚了就有反应」。

## 🐛 问题修复

- **鼠标上报型 TUI 收到的是 SGR 滚轮事件而非方向键**（`e1743f1`）：修复 v0.34.2 引入的 100% 回归——切离再切回运行中的 Codex 任务后，Shift+滚轮会滚动输入框的历史记录而不是滚动回显。原因是为备选缓冲区合成的方向键被 Codex 的输入框当成「上/下」做历史切换。现改为合成与真实滚轮等价的 SGR 鼠标滚轮序列，TUI 按滚轮语义处理；终端快照/恢复链路对鼠标模式（?1002h/?1006h）的保真补了回归测试。
- **鼠标上报激活期间强制本地拖选**（`b63f3c4`）：滚轮修好后，用户反馈 Codex 运行期间不按 Shift 仍拖不出选区高亮。原因是 xterm 6.0 中鼠标上报开启时整个选区服务被禁用，普通拖动不会产生高亮（Shift+拖选因独立路径得以幸存）。现在捕获阶段把左键按下/拖动/抬起事件以带 Shift 修饰的克隆重新分发（带防重入标记），恢复不按 Shift 的自然拖选。
- **快速滚动不再越滚越滞后**（`956ea65`）：修复上一优化后「前几下跟手、越滚越落后」的问题。Codex TUI 每消费一条滚轮上报都整屏重绘，输入消费速率固定；不限速时快速滚动会积压几十条上报，越积越迟。现在对发往备选缓冲区 TUI 的滚轮上报做 30ms 窗口节流（约每秒 33 行上限），窗口内增量合并、超出单包 3 行上限的部分丢弃——快速甩动滚轮时丢掉多余行数不可感知，队列排空后每条上报立即生效。

## ⚠️ 行为变更

- **v0.34.2 的「Shift+滚轮合成方向键」方案已被替换**（`e1743f1`、`3ac9419`）：v0.34.2 宣传的备选缓冲区下合成方向键的做法存在回归（方向键被 Codex 输入框当成历史切换），本版改为合成 SGR 滚轮事件；同时普通滚轮不再需要按住 Shift，Shift+滚轮作为兼容路径保留。升级后无需任何快捷键，滚轮和拖选开箱即用。
- **连续快速滚动的合成上报会被节流合并**（`956ea65`、`3ed2feb`）：同一滚轮事件的同向合成上报合并为一次 IPC 发送；发往 TUI 的滚轮上报按 30ms 窗口节流并限制单包行数。正常滚动手感不变，极端快速甩动时部分多余滚动行会被丢弃。
