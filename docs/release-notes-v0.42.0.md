# Nezha v0.42.0 发版公告

Nezha v0.42.0 正式发布！本版新增 Codex 工作区内免逐条审批开关，改善账号切换后的模型选择，并修复云效批量加入计划部分失败后无法恢复的问题。

## 🚀 新特性

### Codex 审批设置（settings / codex）

- **可选工作区内免逐条审批**（`444a84e`、`5c66fcd`，#120）：应用设置新增开关，默认关闭。开启后，Codex 的 ask 模式使用工作区可写沙箱与按需审批，减少并行工具调用因逐条等待审批而长时间停滞的情况；PTY 与 structured 两种运行通道均生效，越界请求仍需审批。开关在后续启动、分叉或恢复任务时读取，已运行的进程需重新启动后生效。

### 云效回写（yunxiao）

- **评论按 Markdown 原文发布**（`3e401cd`）：开发、测试与价值评分评论保留表格、列表、加粗和标题，避免评分明细被压成普通段落。测试指引按「用例 / 前置 / 步骤与预期」组织，每一步操作都对应预期结果。

## 🐛 问题修复

### Codex 会话与模型（codex）

- **账号或模型提供方切换后刷新模型列表**（`d8f90c0`）：启动应用或打开模型选择器时，重新获取当前账号可用的模型，优先采用实时结果，避免旧提供方的模型残留为可选项。加载失败时提供错误提示与重试入口；显式配置的离线模型目录仍可作为回退来源。
- **避免 structured 任务遗漏线程身份**（`5a33ba7`，#116）：修复新建与恢复任务时，线程启动通知可能早于事件订阅到达的问题，使任务会话关联与后续对话能够取得线程信息。

### 云效计划（yunxiao / delivery-plan）

- **批量加入计划支持部分失败后的恢复**（`58ceb42`，#121）：已成功的条目照常保存，部分失败时展示「成功 / 无需处理 / 失败 / 未处理」摘要，并可只重试失败和未处理条目。已属于其他计划的议题在回写前拦截，避免云效已修改而本地计划缺失的情况。

## ⚠️ 行为变更

- **开启审批开关后，工作区内操作可自动执行**（`444a84e`、`5c66fcd`）：该开关允许工作区内的写操作，不仅限于只读命令；需要逐条把关时，请保持默认关闭。
- **「待开发」议题可补入本地计划**（`58ceb42`，#121）：重复添加时跳过云效写入并补齐本地归属，不再因该状态拒绝整批操作。人工在云效设为「待开发」的议题同样按此规则处理；已有其他本地计划归属的条目仍会被拒绝。
- **测试评论使用纯文本字段，评分评论保留草稿原样**（`3e401cd`、`7193a8f`）：修改分支与修改文件字段不再强制加粗；价值评分评论不附加装饰性标题、编号或议题名，保留 Markdown 发布带来的排版修复。
