# 议题管理全流程闭环 · 说明文档

> 整理日期：2026-10-09
> 适用范围：使用 Nezha 云效集成进行议题（工作项）排期、开发、合并、完结的完整生命周期。
> 关联文档：[`yunxiao-plan-board-v2.md`](./yunxiao-plan-board-v2.md)（计划看板）· [`yunxiao-plan-append-issues-v1.md`](./yunxiao-plan-append-issues-v1.md)（追加议题）· [`yunxiao-issues-integration-v1.md`](./yunxiao-issues-integration-v1.md)（议题集成）

## 1. 流程总览

议题从「需求确认」到「完结归档」共 6 个环节，前 4 步在云效与 Nezha 之间双向回写数据，后 2 步在 Codeup 与云效侧收口：

```
云效（人工确认）          Nezha（排期与开发）                    Codeup / 云效（收口）
┌─────────────┐      ┌──────────────────────────┐      ┌──────────────────────┐
│ ① 状态改已确认 │      │ ② 按计划完成时间圈定议题池  │      │ ⑤ 发起分支合并（MR）    │
│   标记计划完成时间│──▶│ ③ 创建计划（分支+完成时间） │──▶   │ ⑥ 手工标记议题完成     │
└─────────────┘      │ ④ 议题加入计划→自动回写     │      │   （后续考虑合并自动标记）│
                     └──────────────────────────┘      └──────────────────────┘
```

| 步骤 | 操作位置 | 谁 | 关键产物 |
|---|---|---|---|
| ① 确认议题 | 云效 Web | 需求确认人 | 议题状态＝已确认；「计划完成时间」字段有值 |
| ② 圈定议题池 | Nezha 云效视图 | 排期人 | 按计划完成时间范围过滤出的候选议题列表 |
| ③ 创建计划 | Nezha 计划看板 | 排期人 | 计划（关联分支 + 计划完成时间） |
| ④ 议题入计划 | Nezha 计划详情 | 排期人 | 议题状态＝待开发；开始/完成时间、负责人已回写 |
| ⑤ 分支合并 | Nezha 合并中心（Merge Hub） | 开发/评审人 | 计划分支 MR 合入目标分支，计划状态＝merged |
| ⑥ 议题完结 | 云效 Web（当前） | 开发/确认人 | 议题状态＝已完成 |

## 2. 各步骤详细说明

### 步骤 ① 云效确认议题并标记计划完成时间

**操作位置：** 云效 Web 端（人工操作，Nezha 不代做需求确认）。

1. 在云效项目中评审通过后，将议题状态从「待确认」改为**「已确认」**。
2. 在议题的**「计划完成时间」自定义字段**上标记本次排期承诺的完成日期。

**为什么需要这一步：** 「计划完成时间」是后续一切自动化的锚点——步骤 ② 靠它圈定议题池，步骤 ④ 会把它回写为计划的统一完成时间。没有该字段的议题无法进入排期范围。

**注意事项：**
- 「计划完成时间」是云效的自定义字段（非工作流内置状态字段），Nezha 通过字段名称探测其字段 ID；若项目未配置该字段，Nezha 侧的过滤器会自动隐藏，需先在云效项目设置中补配。
- 此处标记的是「这个议题期望何时完成」，与步骤 ③ 中计划本身的完成时间（创建计划时填写）是两个概念；步骤 ④ 入计划时会以计划的完成时间覆盖回写。

### 步骤 ② Nezha 云效视图中按计划完成时间圈定议题池

**操作位置：** Nezha → 云效视图（`YunxiaoView`）→ 筛选栏「计划完成时间」过滤器（`FilterPlanEndSelect`）。

1. 打开云效议题列表，点击筛选栏的「计划完成时间」过滤器。
2. 选择范围，两种方式：
   - **快捷预设**：本周 / 本月；
   - **自定义起止**：手动输入开始与结束日期（闭区间，BETWEEN 条件）。
3. 列表实时过滤出「计划完成时间落在该范围内」的议题，即为本期候选议题池。卡片上的时间徽标若已逾期（非终态且早于今天）会标红提示。

**为什么需要这一步：** 排期人不需要逐条翻议题，一个时间窗就能圈出本期要交付的全部需求，作为步骤 ④「添加到计划」的勾选来源。

**注意事项：**
- 过滤走云效 OpenAPI 条件查询（按探测到的字段 ID 拼 BETWEEN），支持 300ms 防抖，大列表不卡顿。
- 已被其它存活计划占用的议题会在后续步骤 ④ 中被整体拒绝（单计划归属约束），此处仅是候选池。

### 步骤 ③ 创建计划（关联分支 + 计划完成时间）

**操作位置：** Nezha → 计划看板 →「创建计划」（`CreatePlanDialog`）。

创建计划时需填写：

| 字段 | 必填 | 说明 |
|---|---|---|
| 关联分支 | 是 | 计划的交付分支（可从现有分支选择，或由 Nezha 按命名规则预览生成，创建前会做分支冲突预检） |
| 计划完成时间 | 是 | yyyy-MM-dd 日期；**创建后不可修改**——因为后续添加议题时要拿它回写云效议题的「计划完成时间」字段 |
| worktree 范围 | 否 | 计划分支落在主工作区或独立 worktree |

**为什么需要这一步：** 计划是本次交付的执行载体——一个计划对应一条分支、一个完成时间承诺，后续 MR 与议题完结都以计划为单位组织。

**注意事项：**
- 计划完成时间创建后**不可改**（本地字段 `planEndDate`），旧版本创建的缺失该字段的计划无法添加议题，需重建。
- 分支冲突预检（`check_delivery_plan_branch`）会在提交前探测远端/本地同名分支，避免撞名。

### 步骤 ④ 将议题添加到计划（自动回写云效）

**操作位置：** Nezha → 计划详情 →「添加议题」（`AddToPlanDialog`），勾选步骤 ② 圈定的议题。

选中目标计划并确认后，Nezha 后端对每条议题执行**原子回写**（任一失败整批阻断，不产生半加入状态）：

| 回写项 | 写入值 | 说明 |
|---|---|---|
| 状态 | **待开发** | 云效工作流状态切换；表示已进入开发排期 |
| 计划开始时间 | **当前时间**（默认取加入当天） | 云效工作流切「待开发」时校验必填，不写会 400 |
| 计划完成时间 | 计划的完成时间（步骤 ③ 填写的值） | 覆盖议题原有值，与计划对齐 |
| 负责人 | 当前令牌用户 | 即执行该操作的账号本人 |

**为什么需要这一步：** 这是整个闭环里「Nezha → 云效」方向的核心回写：加入计划的动作一次性把排期信息（起止时间、负责人）和状态流转（待开发）同步回云效，云效侧无需任何手工重复录入。

**注意事项：**
- 已是「待开发」的议题会被后端拒绝（防止重复加入）；已属其它活跃计划的议题整批拒绝（单计划归属）。
- 从计划移出议题时同样有反向回写：状态回退「已确认」并清空计划开始/完成时间。

### 步骤 ⑤ 计划完成后发起分支合并

**操作位置：** Nezha → 合并中心（Merge Hub，`MergeHubView`）/ 计划详情。

计划下所有议题开发完成、代码就绪后：

1. 在合并中心找到该计划对应的合并请求（MR），可先执行**拉取代码 / 代码审查**（审查报告可回写云效 MR 评论）。
2. 点击**「分支合并」**，由 Agent 执行合并；若审查判定存在阻止级 fail 标记，会弹二次确认。
3. 合并成功后计划状态流转为 **merged**（计划状态机：`create→active`、`create_mr→review`、`merge→merged`、`close→closed`）。

**为什么需要这一步：** 计划分支承载了本计划全部议题的代码变更，合并即交付动作的完成；MR 是代码评审与回滚的边界。

**注意事项：**
- 合并前请先拉取代码，否则提示「请先拉取代码，再执行分支合并」。
- 计划关联的 MR 状态（opened / approved / merged / rejected / closed）会回填到计划详情展示。

### 步骤 ⑥ 将议题手工标记为完成

**操作位置：** 云效 Web 端（当前版本为手工操作）。

合并成功后，开发/确认人在云效上把本计划对应的议题逐条状态置为**「已完成」**，议题生命周期收口。

**现状与演进：**
- **当前**：手工标记。合并动作发生在 Codeup 侧，与议题状态之间还没有自动联动，由人判断「合并成功＝需求完成」是否成立（可能还有验收、回归等收尾动作）。
- **后续考虑**：**合并成功后自动标记议题完成**——即计划 MR 达到 merged 状态时，Nezha 批量将该计划成员议题状态写为「已完成」（后端已有 `set_workitem_done` 同类回写能力，知识沉淀闭环已使用同款机制），省去逐条手工操作。该自动化尚未实现，实现前请保持手工标记，避免云效侧状态与实际交付脱节。

## 3. 状态与数据回写全景

| 时刻 | 触发动作 | 云效议题侧变化 | 方向 |
|---|---|---|---|
| ① | 人工确认 | 状态：待确认 → 已确认；计划完成时间字段标记 | 云效内 |
| ④ | 议题加入计划 | 状态 → 待开发；计划开始时间＝当天；计划完成时间＝计划值；负责人＝当前用户 | Nezha → 云效 |
| ④' | 议题移出计划 | 状态回退已确认；清空计划开始/完成时间 | Nezha → 云效 |
| ⑤ | MR 状态变化 | （云效 MR 评论可选回写审查报告） | Nezha → Codeup/云效 |
| ⑥ | 标记完成（当前手工） | 状态 → 已完成 | 云效内 |

**贯穿字段**：`计划完成时间`（云效自定义字段）——① 标记、② 过滤、③ 计划承载、④ 回写对齐，是整条闭环的数据主键。

## 4. 常见问题

**Q1：过滤器里看不到「计划完成时间」？**
项目未配置该名称的自定义字段，Nezha 探测不到字段 ID 时自动隐藏过滤器。先到云效项目设置添加名为「计划完成时间」的自定义字段。

**Q2：添加议题时报「已是待开发状态，不能重复加入计划」？**
该议题此前已加入过计划。若要换计划，先从原计划移出（状态回退已确认）再添加。

**Q3：添加议题时报「所选计划缺少计划完成时间（旧计划请重建）」？**
该计划创建于旧版本、未携带计划完成时间字段。因回写云效必须依赖该值，请重建计划。

**Q4：合并成功了，云效议题还是「待开发」？**
正常现象——议题完结目前是步骤 ⑥ 的手工动作，自动标记完成在规划中。请到云效手工置为「已完成」。
