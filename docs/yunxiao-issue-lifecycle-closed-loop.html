2六步详解

每一步在哪里做、做什么、为什么，以及容易踩的坑。

1

云效确认议题

手工
📍 云效 Web（Nezha 不代做需求确认）

做什么：评审通过后，把议题状态从「待确认」改为「已确认」，并在「计划完成时间」自定义字段上标记承诺完成日期。

为什么：这是后续一切自动化的锚点——没有该字段的议题进不了排期范围。

  • 「计划完成时间」是自定义字段，需项目预先配置
  • 此处标记的是议题期望完成时间，入计划时会被计划值覆盖对齐
2

圈定议题池

手工
📍 Nezha → 云效视图 → 筛选栏「计划完成时间」

做什么：用时间过滤器圈出候选议题——支持本周 / 本月快捷预设，或自定义起止日期（闭区间）。

为什么：一个时间窗就能圈出本期要交付的全部需求，作为步骤 ④ 的勾选来源。

  • 卡片时间徽标已逾期（非终态且早于今天）会标红
  • 已被其它活跃计划占用的议题，后续加入时会被拒绝
3

创建计划

手工计划
📍 Nezha → 计划看板 →「创建计划」

做什么：填写关联分支（可预览生成、冲突预检）与计划完成时间（yyyy-MM-dd），可选独立 worktree。

为什么：计划是交付的执行载体——一个计划对应一条分支、一个完成时间承诺。

  • 计划完成时间创建后不可改（添加议题时要拿它回写云效）
  • 旧版本创建、缺该字段的计划无法添加议题，需重建
4

议题加入计划

自动回写
📍 Nezha → 计划详情 →「添加议题」

做什么：勾选议题池中的议题加入计划，后端逐条原子回写，任一失败整批阻断：

  • 状态 → 「待开发」（进入开发排期）
  • 计划开始时间 → 当前时间（加入当天，云效切状态必填）
  • 计划完成时间 → 计划的完成时间（对齐覆盖）
  • 负责人 → 当前令牌用户
已是「待开发」→ 拒绝重复加入 移出议题 → 状态回退「已确认」并清空起止时间
5

发起分支合并

Agent 执行
📍 Nezha → 合并中心（Merge Hub）

做什么：计划内议题开发就绪后，在合并中心先拉取代码 / 代码审查（审查报告可回写 MR 评论），再点「分支合并」交给 Agent 执行。

为什么：计划分支承载全部变更，合并即交付完成；MR 是评审与回滚的边界。

  • 存在阻止级审查 fail 时会弹二次确认
  • 合并成功后计划状态流转：active → review → merged
6

议题标记完成

手工 · 自动化规划中
📍 云效 Web（当前为手工操作）

做什么：合并成功后，把本计划对应议题逐条置为「已完成」，议题生命周期收口。

后续考虑：计划 MR 达到 merged 状态时，Nezha 批量自动将成员议题标记完成（同类回写能力已在知识沉淀闭环验证）。实现前请保持手工标记。

合并成功 ≠ 需求完成，可能还有验收 / 回归收尾

3议题状态怎么流转

一条议题从提出到完结，状态共 4 跳：人工确认 1 跳，Nezha 自动 1 跳，人工收口 1 跳。

待确认 ➜人工 · 评审通过（步骤①） 已确认 ➜自动 · 加入计划（步骤④）
＋回写起止时间、负责人 待开发 ➜人工 · 合并成功后（步骤⑥） 已完成

※ 从计划移出议题时自动反向回退：「待开发 → 已确认」，并清空计划起止时间。

5常见问题

排期时最容易遇到的四件事。

过滤器里看不到「计划完成时间」？
项目未配置该名称的自定义字段，Nezha 探测不到字段 ID 时会自动隐藏过滤器。先到云效项目设置添加名为「计划完成时间」的自定义字段。
添加议题时报「已是待开发状态，不能重复加入计划」？
该议题此前已加入过计划。若要换计划，先从原计划移出（状态回退已确认）再添加。
添加议题时报「所选计划缺少计划完成时间（旧计划请重建）」？
该计划创建于旧版本、未携带计划完成时间字段。因回写云效必须依赖该值，请重建计划。
合并成功了，云效议题还是「待开发」？
正常现象——议题完结目前是步骤 ⑥ 的手工动作，「合并成功自动标记完成」在规划中。请先到云效手工置为「已完成」。
