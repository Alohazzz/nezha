# Nezha v0.43.1 发版公告

Nezha v0.43.1 正式发布！本版修复 Codex 结构化模式的权限与审批同步，补齐各任务入口的运行模式选择，并改善合并冲突未完成时的接续与现场保留。

## 🐛 问题修复

### Codex 权限与审批（codex）

- **恢复结构化会话时正确应用任务权限**（`4449bbb`）：续聊时重新传入任务的工作目录、审批策略和沙箱设置，避免恢复后权限行为与任务配置不一致。
- **文件修改审批可以正常处理**（`4449bbb`）：需要确认的文件修改不再被当作不支持的请求拒绝；审批卡片展示授权目录及可获取的变更文件，支持批准、拒绝和取消。
- **及时清除已处理的审批与提问**（`4449bbb`）：服务端确认请求已处理或撤销后，界面同步移除对应卡片并更新等待状态；旧提问的延迟回调不会误清除新提问，任务结束后也会清理残留问答卡片。

### Codex 运行模式与分叉（codex）

- **各任务入口一致遵循全局运行模式**（`de802be`）：补齐代码审查、合并、分叉和派生任务等入口对「Codex 运行模式」设置的读取，避免选择结构化模式后仍意外进入终端模式；已有任务的续聊继续使用原有通道。
- **结构化分叉保留历史并支持后续对话**（`de802be`）：从已有会话分叉时创建独立会话，等待用户输入后再开始新一轮；结构化启动失败时会提示并回退到终端模式。

### 合并冲突恢复（codeup）

- **普通冲突和补丁失败不再过早终止合并**（`de802be`）：合并助手可以读取、编辑文件并执行验证；补丁因上下文不匹配而失败时，继续核对双方修改并调整处理方式，避免把可恢复的中间状态当作最终失败。
- **未完成的合并保留现场并有限接续**（`de802be`）：清理代码文件夹前先检查 Git 状态；确认仍有本次合并冲突或未完成的合并时，在同一会话中最多自动接续两次，保留已修改及已暂存内容。用户取消或标记完成后停止自动接续，其他未提交修改也不会被强制清理。

## 📝 文档

- **补充批量加入计划部分失败的恢复提案**（`05d053f`）：记录云效回写部分成功、本地计划归属缺失时的触发场景，提出逐条结果摘要与重试方案。该提交仅为提案文档，本版尚未实现其中的产品改动。
