# Nezha v0.34.0 发版公告

Nezha v0.34.0 正式发布！本版本围绕**方案执行的两条链路加固**：不同交付方案的待办现在可以并行跑（并发槽位按方案分池），云效 MR 的生命周期状态会实时同步回方案板；另修复了价值评分解析器对「指标」笔误的兼容问题与移出交付计划后议题无法重新导入的问题。

## 🚀 新特性

### 方案编排（plan）

- **不同方案的待办可以并行执行**（`005b3de`）：方案待办的并发槽位此前按「项目」一池总控，同一项目里同时只能跑一个方案的待办，另一个方案即使互不相干也只能排队。现在槽位池按「项目 + 方案」分池——**同一方案的待办仍然互斥串行，不同方案之间可以并行**，普通任务则落回项目公共池、与一切互斥（主工作区共享）。排队详情的「谁在跑」只列出占着同方案槽位的任务，排队文案也从「同项目」改为「同方案」（中英同步）。手动点击 ▶ 启动与自动接续共用同一套槽位判定，不会绕过上限。

### 交付计划（delivery-plan）

- **移出交付计划后级联解除方案占用**（`350e2e5`）：把成员从交付计划移除后，该议题此前仍残留在方案快照里，云效议题列表的「已导入」守卫会继续命中，导致议题**无法重新导入**。现在移除时会把它从仍占用它的方案快照里一并剔除（剔空后方案置为已取消并落盘），议题可正常重新导入。

## 🐛 问题修复

- **方案状态与云效 MR 生命周期实时同步**（`d9b7d7d`，#114，#115）：提交 MR 后方案在磁盘上已进入「评审中」，但弹窗把返回的更新结果丢掉了，UI 一直显示「进行中」，直到重启才刷新——期间再次提交 MR 还会被后端拒绝。合并中心场景更严重：合并任务只做 git push、从不回写方案，「评审中」的方案永远不会收敛到「已合并 / 已关闭」。现在：提交 MR 弹窗立即把更新后的方案写回列表；新增 `sync_delivery_plan_mr` 命令把云效 MR 的实时状态（已合并 / 已关闭 / 已拒绝 / 评审中各态）映射到方案上；对绕过平台、由 agent 直接 git merge 的场景提供 git 兜底判定（源分支已全部合入目标分支即视为已合并）；合并任务完成时按源分支查找方案并同步；进入方案板与选中「评审中」方案时会自动重新同步，残留的过期状态可以自愈。
- **价值评分解析器兼容「指标」笔误**（`3243f79`）：模型偶发把「核心指数」写成「核心指标」，Rust / TS 两侧解析器都匹配不到指数行，评论正常发出但云效议题的字段回写为空。标签匹配扩展为「绩效 / 核心 / 优先 × 指数 / 指标 × 中英冒号」共 12 个变体，取值优先级不变（绩效 > 核心 > 优先）。
